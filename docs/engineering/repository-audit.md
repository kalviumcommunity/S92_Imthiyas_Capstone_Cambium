## 1. Executive Summary & Architectural Verdict

Cambium is structured as a **focused, modular full-stack monorepo** supporting the Enterprise Research Operating System. The repository root contains **10 top-level functional directories** and standard multi-runtime configuration files.

### Repository Verdict
- **Foundation Quality**: **Strong**. The separation of concerns between client (`client/`), server (`server/`), design tokens (`tokens/`), operational tooling (`scripts/`), documentation (`docs/`), test harnesses (`tests/`), and API definitions (`bruno/`) is logical, predictable, and compliant with modern monorepo engineering standards.
- **Clutter Assessment**: **Low**. There are no redundant artificial layers (e.g. nested `infrastructure/`, `configuration/`, `engineering/` shells). The root contains only files with legitimate repository-level scope.
- **Action Taken**: Refined script organization (isolated historical logo calibration scripts), tightened `.gitignore` against test runner artifacts (`.playwright-mcp/`), stabilized Vitest server test runner under high-concurrency Node runtimes, and established formal documentation information architecture.

## 4. Analysis by Engineering Subsystem

### 4.1 Frontend Tier (`client/`)
- **Framework**: Next.js 15.2.1 (App Router) + React 19.0.0 + TypeScript 5.7.3.
- **Route Architecture**: 53 statically generated pages across Public, Auth, and 23 Protected Enterprise routes.
- **State Architecture**: Global server cache via `@tanstack/react-query`, UI state via `zustand`, URL state via native router hooks.
- **Styling**: Strictly tokenized via `tokens/cambium.tokens.json` and `client/app/globals.css`.
- **Finding**: High code discipline. All 53 routes build cleanly with `0 TypeScript errors`.

### 4.2 Backend API Tier (`server/`)
- **Framework**: NestJS 10.4 (modular architecture) + Express + TypeORM + PostgreSQL 16.
- **Database Access**: 17 TypeORM entities with pgvector 1536-dimensional HNSW cosine indexing.
- **Testing**: 24 Vitest test suites (117 tests).
- **Finding**: Vitest worker forks encountered V8 Zone memory allocation exhaustion on Windows under Node.js 24 when spawning unconstrained child processes.
- **Action Implemented**: Updated `server/package.json` to configure `"test": "vitest run --pool=threads"`. Test execution time dropped from 51s to 23s with 100% test pass rate (24/24 files, 117/117 tests).

### 4.3 Testing Architecture
- **Root Unit Suite** (`tests/unit/`): 9 Jest suites, 82 unit tests covering citation formatting, boolean AST query compilation, token contrast (WCAG 2.2 AA / APCA), deadline urgency math, offline sync queues, cryptographic audit ledger, and inverted index search.
- **Server Unit Suite** (`server/src/`): 24 Vitest suites, 117 unit tests covering auth, RBAC guards, opportunity management, OCR sandboxing, Redis caching, Redlock concurrency, outbox dispatch, and SAML SSO.
- **E2E Suite** (`tests/e2e/`): 6 Playwright specifications covering authentication, discovery, Gemini agent reader, citation graph, Axe-Core accessibility, and deployment smoke probes.

### 4.4 Operational Scripts (`scripts/`)
- **Operational Tools (Kept at `scripts/` root)**:
  - `verify-env.mjs`: Validates required environment variables for development and production.
  - `verify-db.mjs`: Tests PostgreSQL connectivity, pgvector extension, and TypeORM table readiness.
  - `verify-proxy.mjs`: Probes Nginx and Caddy reverse proxy routing.
  - `health-check.mjs`: Executes multi-container health probes across HTTP, DB, and Redis.
  - `backup-db.mjs`, `backup-db.ps1`, `backup-db.sh`: Generates compressed, SHA-256 checksummed database dumps.
  - `restore-db.mjs`, `restore-db.ps1`, `restore-db.sh`: Restores database dumps with schema validation.
  - `smoke-test.mjs`: Comprehensive post-deployment smoke probe suite.
  - `verify-ai-autocomplete.mjs`: Validates Gemini LLM autocomplete latency and RAG fallback.
  - `generate-production-audit.mjs`: Generates audit artifacts.
- **Development Scratch Utilities**:
  - Moved 8 one-off logo optical calibration scripts into `scripts/development/logo-calibration/` to maintain a pristine, predictable `scripts/` root.

## 5. Audit Classification Matrix

### Verified Findings
1. All 10 root directories have distinct, non-overlapping ownership boundaries.
2. No sensitive credentials or secrets exist in any committed configuration file or `.env.example`.
3. Database backup dumps in `backups/` are strictly ignored by `.gitignore`; only `backups/.gitkeep` is tracked.
4. The monorepo has two distinct test runners (`jest` for root/client utility specs, `vitest` for NestJS backend specs) with non-conflicting configurations.
5. All 53 Next.js pages compile statically in `10.5s` with zero errors.

### Suspected Issues & Resolutions
1. **Node 24 Vitest Memory Exhaustion**: Vitest's default child-process fork pool suffered zone memory errors on Windows under Node.js 24.
   - *Resolution*: Configured `--pool=threads` in `server/package.json`. Tests now execute in 23s with 100% stability.
2. **Untracked Playwright MCP Directory**: The `.playwright-mcp/` directory created by MCP tools was untracked.
   - *Resolution*: Added `.playwright-mcp/` to `.gitignore`.
3. **Outdated Technology Claim in Careers Page**: `careers/page.tsx` referenced FastAPI services.
   - *Resolution*: Updated to "Next.js and NestJS enterprise services" to align with ADR 0002.
4. **Outdated Container Diagram in Architecture Template**: `docs/templates/ARCHITECTURE.md` referenced a Python FastAPI container.
   - *Resolution*: Updated container definition to "TypeScript, NestJS 10, TypeORM, Gemini Embedding".

### Recommended Improvements Implemented
- Isolated scratch logo scripts into `scripts/development/logo-calibration/`.
- Restructured `docs/` into 7 canonical information architecture domains (`architecture/`, `engineering/`, `operations/`, `product/`, `security/`, `testing/`, `decisions/`).
- Documented branch and PR audit in `docs/engineering/pull-request-review.md`.
- Documented release process and semantic versioning in `docs/operations/release-process.md`.
